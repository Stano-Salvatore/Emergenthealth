# Audit and plan, 15 September 2026

What to fix, what to add, what to take out. Gathered three ways: a read of the
code (all 39 dashboard pages, the 210 API routes, the 68 Prisma models, the
engine, the chat builder and the Java), the production error table on Vercel
for the last seven days, and a render of every dashboard page at phone width
against a seeded local database (`npm run smoke`). Every claim below has a
file behind it; where the render confirmed a code finding it says so.

Production is clean: the only error group in seven days is the backup export
failure fixed on the 11th, last seen on the 10th. Vercel Web Analytics is not
enabled, so nothing here can say which of the 39 pages are actually opened.
That gap is item A5.

## A. Fix now

Correctness and honesty, each small enough for one session.

1. **The Home gauge grades a relative score on an absolute scale.** The daily
   score is "0–100 where 50 is a typical day for this person"
   (`daily-score.ts:120`), and `scoreGrade` calls 41–59 "About your usual" in
   sky blue. The mobile Home gauge colours the same number through
   `scoreStatus` (`score-color.ts:37`), which is the goal scale: 85+ green,
   70+ amber, else red. The render shows it: a 52 painted red on Home beside
   7.4h of sleep, 9.1k steps and readiness 84, while the Insights page calls
   the same 52 "About your usual". Colour the gauge from `scoreGrade`.
2. **Waist is written to a table the engine never reads.** The Body page has
   two forms. "Log measurements" (`body/page.tsx:309`) posts to
   `/api/body-measurements`, which inserts into `BodyMeasurementLog`
   (waist, chest, hips, neck, bicep, body fat, timestamped). "Log measurement"
   (`:801`) posts to `/api/body`, which upserts `BodyMeasurement` (dated).
   `correlations.ts:881` reads only `BodyMeasurement`. Waist typed into the
   first form is invisible to the `body_waist_*` families, which is a
   stronger reason than "rarely enough weigh-ins" for why they never card.
   One form, one table; migrate the log rows across.
3. **Four families are charged twice to the same FDR pool.** `caffeine_sleep`
   (`correlations.ts:1459`), `alcohol_sleep` (`:1489`),
   `caffeine_deep_sleep` (`:2622`) and `alcohol_rem_sleep` (`:2632`) test the
   same cut against the same next-night outcome as the sleep panel's
   `sleep_panel_caffeine`, `sleep_panel_alcohol` and their `_deep` / `_rem`
   aspects. The only difference is that the panel sets silent days aside and
   the older four read them as zero, so the two can disagree on the same
   screen. Delete the four older ones; every other card's Benjamini-Hochberg
   bar tightens for free. Bump `ENGINE_VERSION`.
4. **A calendar failure renders as a clear day.** `getUpcomingEvents`
   (`google-calendar.ts:198`) swallows every error into an empty list, and
   the dashboard says "No events · Enjoy your day!" (`dashboard/page.tsx:673`)
   and mobile "Nothing coming up 🌿" (`MobileToday.tsx:272`). A lapsed Google
   grant reads as a free afternoon. Return `{ events, error }` and say
   "Calendar didn't answer" instead.
5. **A user with no wearable sees a red 0 labelled TODAY.**
   `MobileToday.tsx:196–222`: `stale` is only true when there is an older
   health row, so `healthDate == null` falls through to a score of 0 in red,
   four empty pillars and no explainer. First screen on a new phone. Treat
   null as its own state and render "No data yet".
6. **The onboarding card is invisible on the first visit.** `QuickStart.tsx`
   hides itself until `eh_first_seen` exists, and the key is written after
   the paint that checked it, with no re-render. The card built for the
   empty dashboard is the one a new user does not get. Its push step is also
   unachievable inside the APK, where the `PushNotifications` card renders
   null, so `allDone` never fires.
7. **Copy that points at things that are not there.** "Settings →
   Integrations" (`health/page.tsx:290`, `stats/page.tsx:139`): no such
   section; the cards live under "Data connections", collapsed by default.
   "Tap the ⭐ on any pattern" (`WatchedPatterns.tsx:57`) on the Insights page,
   whose cards have no star (the star is only in the dashboard widget;
   confirmed in the render). "Go to Settings → Manage Billing" and "Settings →
   Push Notifications" in `HelpCard.tsx` on a build where neither renders.
8. **The Health header attributes everything to a ring.** "30 days of data ·
   synced from Oura Ring" (`health/page.tsx:267`) prints regardless of
   `isOuraConnected`; the render shows it on seeded rows with `source:
   "app"`. Derive the source from the rows.
9. **Stats and Week print an empty shell under their empty state.**
   `stats/page.tsx:126` onward and `week/page.tsx:195` onward render "No
   trends yet" and then four "—" cards, two "0d" streaks and an HRV verdict
   that defaults to "stable" from nothing. Return after the empty state.
10. **Three template strings judge.** "Keep it up!" (`health/page.tsx:413`),
    "great!" / "keep going" (`stats/page.tsx:280`), "Nice work"
    (`checkin/page.tsx:410`). Scripted surfaces report and never conclude;
    the lint in `insight-lint.ts` does not cover page copy. Drop the verdicts
    and extend the lint.
11. **Settings says "Everything connected is working" over nothing
    connected.** `StatusOverview.tsx:60` counts only bad and warn rows, so an
    account with every row "off" reads as healthy. Reminders shows a green
    tick for an empty table (`dashboard/page.tsx:738`). Same family.
12. **Two Android alarms share request code 920007.**
    `EmergyWakeService.RESTART_REQUEST` (`:66`) and
    `HeadAlarmReceiver.WATCHDOG_REQUEST` (`:37`), both broadcast to the same
    receiver. They survive only because the actions differ; reuse an action
    and `cancelWatchdog` cancels the wake restart. Give the watchdog its own
    code. **The watchdog also does not cover the chat head**:
    `HeadAlarmReceiver:108` re-runs location and wake only, and
    `EmergyHeadService` is still on the `START_STICKY` path the watchdog
    exists because Samsung ignores. Both need an APK.
13. **The chat prefix loads data the build cannot have.** The system prompt
    builder fetches 100 `Transaction` rows for "## Finances (this month)"
    (`claude.ts:2076`) while finances is held back, and queries screen time
    for a table nothing on the APK can write. Both sit inside the cached
    prefix, paid on every cache write. Gate the sections on the feature flag
    and on the source having rows.

## B. Subtract

Things that cost attention, tokens or false-discovery budget and return
nothing today.

1. **Screen time, all of it, until the permission question is answered.**
   The manifest never declares `PACKAGE_USAGE_STATS` (open thread in the
   handoff), so: the dashboard card and the Settings card point at a grant
   that cannot happen; six `screen_*` families, a combo condition, an
   interaction and a symptom suspect in the engine spend FDR budget on a
   column that is always empty; and the chat prefix carries a section for it.
   Either declare the permission and answer the Play Console form, or remove
   the two cards, gate the families on the column having rows, and drop the
   prompt section. The present state is the one option that is not honest.
2. **Three dead tables and one dead route.** `FitToken`,
   `GocardlessConnection`, `SaltedgeConnection` have no reader and no writer
   outside the export list. `/api/newsletter` has no caller in `src/` and
   writes `NewsletterSubscriber`, which nothing reads. Drop them.
3. **Two location-correlation endpoints.** `/api/location-correlations`
   (317 lines, used by two components) and `/api/location/correlation`
   (199 lines, used by the Location page) answer the same question. Keep one.
4. **Toggl.** A token table, four routes and MCP tools, no daily log, no
   `DayData` field, not in `SYNC_SOURCES` so the status screen cannot even
   call it quiet. Either give it a log table and a cron so it can correlate,
   or remove it. Half-present is the worst of the three.
5. **A quarter of the engine's battery cannot be asked on this account.**
   Beyond screen time: the three `work_*` families (RescueTime), the two
   money families (finances held back), the waist half of body (A2), the
   per-activity calendar pair, and nine music families without Last.fm. Each
   spends budget the others could use. Gate every family on its source having
   at least one row in the window, once, at the top of the run.

## C. Add

In order of payoff against effort.

1. **A weather cron.** `WeatherLog` is written only by `WeatherWidget` on the
   client when the app is opened, and the correlation engine and the chat
   prompt both read it. A week without opening the app is a week without
   weather in every temperature family. Server-only, no APK, one route on
   the existing schedule.
2. **Bedtime as a sleep-panel cause.** Written up in the handoff's open
   threads with the two snags. The biggest lever on sleep score this account
   has, and it has no card.
3. **Set `EMERGY_CHAT_EFFORT=medium` in production and read the logs for a
   week.** Wired, validated, unset. The `[emergy] turn` line already prints
   the numbers to compare. One environment variable.
4. **Per-turn tool selection.** Every turn ships all 41 tool schemas
   (`claude.ts:109–694`). A log line that slips past the parser still pays
   for the analysis tools. A cheap first pass choosing a subset is the
   model-tiering lever from the handoff in its smallest form.
5. **Vercel Web Analytics.** Free tier, one toggle, and the only way to know
   which of 39 pages are opened. Every subtraction after this one can then
   be argued from a number rather than a guess.
6. **"Test this" on the new cards.** `experiment-suggest.ts:18–27` matches
   outcomes by id suffix, so the panel's `_latency`, `_efficiency` and
   `_restless` aspects and every `combo_*` card have no experiment button.
7. **Pool size on the card.** `InsightResult.pool` drives the FDR grouping
   but nothing renders it, so a card judged inside a pool of six reads the
   same as one judged alone.
8. **Split `correlations.ts`.** 4140 lines, 13 exports, 101 `compareGroups`
   calls, one 1900-line closure. The seam is already cut: a stats module
   (`Split`, the three permutation tests, `assignTiers`, `balancedCut`), a
   loader (lines 692–1230), the families, and the late families. Only two
   routes import the public function.
9. **CI that fails when a manifest patch misses.** `customize-android.py`
   does about twenty string replacements anchored on `</application>` and
   friends, each guarded by a presence check and none asserting the
   replacement landed. The wake-word assets already use `sys.exit("FATAL")`;
   apply it to the manifest blocks. Also lift `APP_URL` in both cron
   workflows into a repository variable; today a domain move sends every
   sync to a 404 while the workflows stay green.
10. **The location queue timer.** Still open from the handoff: `flush()` is
    reachable only from a new fix, so points queued while stationary wait.
    Needs an APK, so batch it with A12.

## D. What the render found

Filled in from `npm run smoke` at 390px against the seeded database.

All 39 routes answered 200, ten of them by redirect (held-back features and
the pages folded into Health and Intake); nothing overlapped the bottom nav,
no skeleton stalled, no page scrolled sideways. The 18 warnings were all the
two expected local ones: the briefing 503 without an API key, and 400s from
sources the demo account never connected.

What reading the screenshots added, none of it expressible as a unit test:

- **Home**: a 52 in red beside four healthy pillars (A1). The header sat on
  "Syncing…" for the whole capture.
- **Health**: "synced from Oura Ring" over rows the seed marked `source:
  "app"` (A8).
- **Insights**: "Tap the ⭐ on any pattern" above cards with no star (A7).
  The score card under it explains 52 as "About your usual", which is what
  Home should have said.
- **Habits**: "Last 30 days —" beside a full heatmap. A seed artefact, not a
  bug: the demo habits are created today, so no past day counts as due
  (`streak.ts:140`). Worth knowing before it is reported again.
- **Stats**: "Bedtime regularity consistent, ±0m" is the seed's constant
  bedtime, not a rounding fault. The empty-shell finding (A9) needs a
  zero-data account to reproduce, which the seed is not.
- **Settings**: the At-a-glance card is the honest model the rest of the app
  should copy. Every unconnected source says so, and the missing
  `CRON_SECRET` is called out in red rather than hidden.
- **Every page** fires sync requests for sources that are not connected
  (the 400s above), one per source per load. `AutoSync.tsx:30–46` should
  check the connection before asking.
